---
description: Порядок добавления нового API-эндпоинта
---

Добавь эндпоинт: $ARGUMENTS. Тег шага [BE]. Сначала задай вопросы, если неясны роль, путь или формат ответа.

Порядок:

1. **Спецификация**: допиши эндпоинт в `docs/Api.md` (путь, метод, доступ, лимит, коды ошибок), при необходимости `docs/Roles.md`. Если в docs противоречие — стоп и вопрос.
2. **Политика доступа**: по умолчанию закрыто (FallbackPolicy). Публичный — `[AllowAnonymous]` на действии. Админский — контроллер `[Authorize(Roles = "Admin")]`. Id пользователя только из токена.
3. **Rate limit**: если эндпоинт чувствительный (вход, заказ, отзыв, перебор) — подбери политику из `RateLimitPolicies`.
4. **Валидация**: FluentValidation для входного DTO; фильтры списков валидируются в контроллере.
5. **Логика**: в Application-сервисе, ошибки через `Result<T>`, контроллер только мапит в HTTP.
6. **Тесты**: на 401 (без токена), на 403 (не та роль), на успех, на ошибку валидации. Обнови `EndpointAuthorizationTests`.
7. **Docs**: сверь `docs/Api.md` с тем, что получилось.
8. Закрой шаг командой `/done`.
