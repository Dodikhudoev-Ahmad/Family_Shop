# Family Shop — мобильное приложение (Expo)

React Native (Expo SDK 57, managed workflow, TypeScript strict). Использует тот же backend, что и сайт: `/api/v1/*`.

## Запуск (Mac)

Без настройки приложение ходит на **боевой** API, а он не пускает чужие origin (CORS), поэтому веб-превью
на `localhost:8081` покажет «Не удалось загрузить категории». Для разработки поднимите локальный бэкенд.

**1. Postgres** (Homebrew, порт 5433):

```bash
brew services start postgresql@16
# если не стартует из-за мёртвого postmaster.pid:
# rm /opt/homebrew/var/postgresql@16/postmaster.pid && brew services restart postgresql@16
```

**2. Бэкенд** (один раз задайте строку подключения, пароль роли `postgres` — ваш):

```bash
cd backend/Api
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Host=localhost;Port=5433;Database=familyshop;Username=postgres;Password=<пароль>"
dotnet run --launch-profile http     # http://localhost:5280, Development: миграции и сидер применятся сами
```

CORS для `http://localhost:8081` включён только в `appsettings.Development.json`, то есть при `ASPNETCORE_ENVIRONMENT=Development`
(профиль `http` его выставляет). На проде этого origin нет.

**3. Мобильное приложение / web-превью:**

```bash
cd mobile
npm install
cp .env.example .env.local           # EXPO_PUBLIC_API_URL=http://localhost:5280/api/v1
npx expo start --web -c              # http://localhost:8081; -c — сбросить кэш после смены переменной
```

В dev-сборке под сообщением об ошибке видно, к какому адресу идёт приложение.

**На телефоне (Expo Go)** `localhost` недоступен: в `.env.local` укажите LAN-адрес Mac, например
`EXPO_PUBLIC_API_URL=http://192.168.1.5:5280/api/v1`, запустите бэкенд на всех интерфейсах
(`dotnet run --launch-profile http --urls http://0.0.0.0:5280`) и `npx expo start -c`.
Нативные запросы CORS не проверяют, добавлять origin не нужно.

Release-сборка отказывается работать с не-`https://` адресом.

## Авторизация (контракт с backend, см. CLAUDE.md §3.4)

- Эндпоинты `/api/v1/auth/mobile/{register,login,refresh,logout}`. Refresh-токен приходит в **теле** JSON.
- **Токены только в `expo-secure-store`** (`src/lib/storage/secureStorage.ts`, режим `WHEN_UNLOCKED_THIS_DEVICE_ONLY`).
  Access-токен (15 мин) живёт только в памяти. AsyncStorage используется лишь для языка, темы, корзины и избранного.
- `deviceId` — UUID, создаётся один раз при первом запуске и хранится в secure store; отправляется с каждым login/register/refresh/logout.
  Сервер хранит только его хеш; refresh с другого устройства отзывает сессию.
- Один общий refresh на всё приложение (`src/lib/api/client.ts`): сервер ротирует refresh-токен при каждом использовании,
  а повтор уже обменянного токена считает кражей и отзывает всю сессию — параллельные refresh недопустимы.
- Сессия отвергнута (401/403) — токены стираются, пользователь разлогинивается; сеть/5xx/429 — сессия сохраняется.
- Токены, пароли и тела запросов никогда не логируются (в `src` нет `console.*`, это проверяет тест).
- Заголовок `X-Client-Type` не используется.

## Структура

```
App.tsx                  провайдеры, шрифты, тема/язык
src/config.ts            адрес API (https в release)
src/lib/api/             клиент, токены, эндпоинты, DTO
src/lib/storage/         secure store (+ in-memory заглушка для web-превью)
src/i18n/                ru/kk/en (словари из frontend + раздел mobile), язык в AsyncStorage, дефолт ru
src/theme/               дизайн-токены (терракота #C17A54, светлая/тёмная, отступы, шрифты), дефолт light
src/state/               Auth, Categories, Cart, Favorites
src/lib/catalog/         чистая логика каталога, перенесённая с сайта: фильтры (resetDependentFilters, ценовые границы),
                         группы размеров, типы (MIN_TYPE_ITEMS=5), остатки, секции главной, безопасные ссылки баннеров
src/state/               + ProductsContext (весь каталог постранично до hasMore:false), useCatalogPages (серверная пагинация)
src/lib/validation.ts    правила форм как на сервере (пароль: буквы+цифры, 8..72 БАЙТА, частые пароли; телефон, адрес,
                         ≤50 позиций и ≤50 шт в позиции) + нейтральные тексты ошибок входа/регистрации
src/state/cartLogic.ts   корзина: общий лимит остатка на товар, лимиты сервера, нормализация сохранённого, сверка с каталогом
src/navigation/          таб-бар (Главная, Каталог, Корзина, Избранное, Профиль) + стеки
src/screens/             Главная (поиск, баннер, плитки категорий, Хиты/Новинки/Скидки), Каталог (2 колонки, фильтры
                         в bottom sheet), Товар (галерея, размеры, корзина, отзывы, похожие), корзина, профиль
```

`.env.local` перекрывает переменную `EXPO_PUBLIC_API_URL`, переданную в командной строке: адрес меняйте в файле.
Язык и тема хранятся в `fs.lang.v2` / `fs.theme.v2` (по умолчанию `ru` и светлая, настройки устройства не читаются);
если превью открылось на другом языке или в тёмной теме, это сохранённый выбор из «Профиля» — переключите его там.

Веб-превью (`npx expo start --web`) нужно только для разработки: secure store на web не существует, поэтому секреты там живут в памяти.

## Корзина, оформление, профиль

- Корзина: позиции `productId+size`, общий лимит остатка на товар, промокод проверяет **сервер** (скидку клиент не считает).
- Оформление — только для вошедших (как на сайте): в заказ уходят id, размеры, количества, телефон, способ получения, адрес и
  **код** промокода; цену и скидку заказа считает только сервер. После успеха корзина очищается, показывается номер `FS-N`.
- Профиль: данные, «Мои заказы» (только свои — id берётся сервером из токена), тема, язык, выход / выход на всех устройствах.
- Отказ сервера (401/403 при refresh) стирает токены и возвращает на форму входа с пометкой «Сессия завершена».
- Офлайн-баннера нет (нужен нативный NetInfo): сетевые ошибки показываются на экране с кнопкой «Повторить».
