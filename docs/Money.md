# Деньги, выручка, время

Источник: `Domain/ValueObjects/Money.cs`, `Application/Services/OrderService.cs`, `PromoCodePolicy.cs`, `Application/Common/StoreClock.cs`, `OrderRepository.GetStatsAsync`, `CLAUDE.md` (3.3).

## Валюта и тип

- Валюта: тенге, ₸ (показывается в UI и сообщениях; в БД и `Money` кода валюты нет, только число).
- `Money` — структура с одним полем `Amount` (decimal). Отрицательное значение — исключение. Операции: `+`, `* int`, сравнения.
- В БД: `decimal(18,2)` (цены товара, `DiscountPrice`, `TotalPrice`, `DiscountAmount`, `OrderItem.Price`).

## Цена заказа

1. Цена строки = `Product.EffectivePrice` (цена со скидкой, если она задана) на момент заказа; сохраняется в `OrderItem.Price`.
2. Подитог = сумма цена × количество.
3. Промокод (если есть) уменьшает подитог; `TotalPrice` — итог после скидки, `DiscountAmount` — размер скидки.
4. Доставка в расчёте не участвует. TODO: уточнить: есть ли плата за доставку (в коде не найдена).

## Промокоды (`PromoCodePolicy.Evaluate`, общая для предпросмотра и заказа)

Отказ, если: не активен; вне `ValidFrom..ValidUntil` (UTC); подитог < `MinOrderAmount`; `UsageCount >= UsageLimit`.
Скидка: процент — `Round(подитог × % / 100, 2)`, с потолком `MaxDiscountAmount`; фиксированная — `DiscountValue`. Скидка не больше подитога. Код приводится к верхнему регистру. Использование увеличивается условным UPDATE в транзакции заказа (откат вместе с заказом).

## Округление

`Math.Round(..., 2)` (банковское округление .NET по умолчанию, `MidpointRounding.ToEven`) только для процентной скидки. TODO: уточнить: нужно ли округление до целых тенге.

## Статистика админки (`/admin/orders/stats`)

| Карточка | Определение |
|---|---|
| Заказов сегодня | заказы за текущие сутки магазина, статус **не** `Cancelled` |
| Выручка сегодня | сумма `TotalPrice` тех же заказов (после скидки) |
| Всего заказов | все когда-либо оформленные, включая отменённые |
| Новых заказов | статус `Created` |

Выручка не привязана к «Доставлен» (оплата при получении). Отменённый заказ денег не приносит, его товар вернулся на склад.

## Часовой пояс

- Настройка `Store:TimeZone`, переменная `Store__TimeZone`, по умолчанию `Asia/Almaty` (UTC+5).
- `StoreClock`: границы «сегодня / неделя (с понедельника) / месяц» — местная полночь магазина, переведённая в UTC. В БД даты только в UTC.
- Фильтр дат на странице «Заказы»: «с» — начало местных суток, «по» — последний момент местного дня (день включён).
- Сервер отдаёт `storeTimeZone` в статистике; сайт показывает даты заказов в этом поясе.
- Новые периодические подсчёты берут границы из `StoreClock`, не из `DateTime.UtcNow.Date`.
- Неизвестный пояс в конфиге — ошибка запуска (кроме `Asia/Almaty` без tzdata: тогда фиксированные +05:00).

## Оплата

Платёжного шлюза нет. Единственный способ — оплата при получении. Истории платежей нет (модуль «Финансы» — открытая задача, см. `PROGRESS.md`).
