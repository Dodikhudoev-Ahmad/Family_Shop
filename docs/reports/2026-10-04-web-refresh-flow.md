# Отчёт: Фаза 14, шаг 7b — refresh на сайте [FE]

Дата: 2026-10-04.

## 1. Итог

В [frontend/src/lib/api.ts](../../frontend/src/lib/api.ts) все refresh-запросы идут через один общий `refreshSession()`, а выход из сессии происходит только при ответе 401/403 на refresh. Сеть и 5xx больше не разлогинивают.

## 2. Причина

Проверка клиентов после шага 7 (после него отзыв сессии виден сразу, и refresh-путь стал важнее) показала два места: `silentRefresh` не делил запрос с refresh после 401 (две параллельные отправки одной cookie, второй получает отказ и разлогинивает), и любая неудача refresh, включая обрыв сети и 5xx, вызывала `setAccessToken(null)`. Mobile уже вёл себя правильно (`unavailable`).

## 3. Что изменено

- [docs/Api.md](../Api.md) — абзац «Поведение сайта» (первым).
- [api.ts](../../frontend/src/lib/api.ts): `refreshSession()` с исходами `ok` / `rejected` / `unavailable`, общий промис сбрасывается в `finally`; `apiFetch` — один повтор, `unavailable` → `ApiError(errors.connect)` без очистки токена; `silentRefresh` — `null` при отказе, ошибка при недоступности (маркер сессии в `AuthContext` сохраняется); `downloadFinanceExport` (второй потребитель refresh) — те же правила. Новых строк в словарях нет: используется `errors.connect`.
- [refreshFlow.test.ts](../../frontend/src/lib/refreshFlow.test.ts) — 17 тестов: один запрос на параллельные `silentRefresh` + 401-refresh и на двойной вызов (StrictMode); освобождение промиса после успеха и после ошибки; 401/403 → выход; сеть, 500/502/503/429/400, нечитаемый 200 → токен сохранён; `silentRefresh` для обоих случаев; один повтор без цикла; скачивание Excel.

## 4. Тесты

- `vitest`: 284 passed в 38 файлах (до шага 267 в 37; в CLAUDE.md было 261, цифра устарела).
- `tsc -b`: чисто. Backend и mobile не менялись.
- Живая проверка в браузере не выполнялась.

## 5. Заметки

- Текст ошибки при недоступности — «Не удалось подключиться к серверу…» (`errors.connect`), не отдельная строка «сервис недоступен».
- 400 и 429 от refresh считаются недоступностью (как в mobile): сессию из-за них не сбрасываем.
- Известное свойство: 401, полученный уже после чужого refresh, запускает ещё один refresh подряд (не параллельно). Cookie к этому моменту новая, сервер это принимает.

## 6. Что проверить на проде

Войти, выключить сеть в DevTools на время запроса к закрытой странице — выхода быть не должно; выйти на другом устройстве («выйти везде») — после ближайшего запроса вход.
