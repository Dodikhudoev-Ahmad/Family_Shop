# Отчёт: Фаза 14, шаг 5 — QuickViewModal, полный ряд размеров [FE]

Дата: 2026-10-04.

## 1. Итог

Быстрый просмотр показывает весь размерный ряд товара, как страница товара. Размеры, которые админ не продаёт, видны приглушёнными и перечёркнутыми и не выбираются. Backend, API и остатки не менялись.

## 2. Причина

Не обрезка (`slice`), не `overflow: hidden` и не фиксированная ширина. Окно перебирало `product.sizes` — только **доступные** размеры, а полный ряд (`product.gridSizes`) не использовало: недоступные размеры просто не выводились. Перенос строки (`flex-wrap`) уже был. Вторая причина дублирования: разметка и стили `.size-btn` жили в странице товара ([ProductPage.tsx](../../frontend/src/pages/ProductPage.tsx)), у окна был свой голый список кнопок без состояний.

## 3. Что изменено

- Новый общий компонент [SizeSelector.tsx](../../frontend/src/components/SizeSelector/SizeSelector.tsx) и [SizeSelector.css](../../frontend/src/components/SizeSelector/SizeSelector.css): один источник разметки, состояний и стилей. Стили `.size-btn` перенесены из [ProductPage.css](../../frontend/src/pages/ProductPage.css) без изменений, добавлены `aria-pressed`, подъём на 1 px при hover (отключается при `prefers-reduced-motion`).
- [ProductPage.tsx](../../frontend/src/pages/ProductPage.tsx): использует `SizeSelector` (поведение, бейдж «в корзине» и пояснение прежние).
- [QuickViewModal.tsx](../../frontend/src/components/QuickView/QuickViewModal.tsx), [QuickViewModal.css](../../frontend/src/components/QuickView/QuickViewModal.css): весь ряд из `gridSizes` (запасной вариант — `sizes` для старых снимков), пояснение для недоступного размера (`aria-live`, без alert), выбранный размер — акцентом, блок размеров не показывается у товаров без сетки; проверка «выберите размер» теперь по всему ряду.
- Docs: [DRIFT.md](../DRIFT.md), B20; [PROGRESS.md](../../PROGRESS.md); [CLAUDE.md](../../CLAUDE.md) (Current Status).

## 6. Пункты задачи

1. Причина найдена и описана — да.
2. Все размеры из API, один источник с страницей товара — да (общий `SizeSelector`).
3. Перенос строки, без горизонтального скролла и overflow на 320 px — да.
4. Недоступные видны, перечёркнуты, не выбираются — да, **но не атрибутом `disabled`, а `aria-disabled`** (как на странице товара): кнопка остаётся в фокусе, экранный диктор читает «недоступен», нажатие объясняет причину. Это решение вместо буквального «disabled». Выбранный — акцент — да; **в тёмной теме акцент — токен `--color-accent` (#D08F68), а не буквально #C17A54** (так задано дизайн-системой).
5. Минимум 44×44 (факт 48×48), hover-анимация, фокус с клавиатуры (`:focus-visible`, был), `aria-pressed` — да.
6. Без `alert()`/`confirm()`, обе темы — да.
7. Backend, API, остатки не менялись — да. Остаток по-прежнему один на товар: «недоступный» = размер, который админ не продаёт, а не «нет остатка по размеру».

## 7. Что проверить на проде

1. Открыть быстрый просмотр товара с частью размеров (например, только M и L): виден весь ряд, остальные перечёркнуты, нажатие объясняет.
2. Товар без размеров (сумка, техника): блока размеров нет, «В корзину» работает.
3. Телефон 320–390 px: ряд переносится, окно не едет вбок.

## 8. Решения и риски

- Выбранный размер в быстром просмотре — акцентом (по задаче); на странице товара остался прежний вид (инверсия цвета текста), чтобы не менять её без запроса. Могут отличаться — скажите, если нужно унифицировать.
- Белый текст на терракоте: контраст ≈ 3,3:1 (жирность 600, 14 px); для WCAG AA нужен ≈ 4,5:1. Кнопка крупная, но это стоит иметь в виду.
- Mobile: быстрого просмотра в приложении нет — паритет не требуется.
