# Статусы заказа и связанные процессы

Источник: `backend/Domain/Entities/Order.cs`, `backend/Application/Services/OrderService.cs`, `claude.md` (3.2, 3.3).

## Статусы (`OrderStatus`)

`Created` (новый) → `Processing` (в обработке) → `Shipped` (отправлен) → `Delivered` (доставлен); `Cancelled` (отменён).

## Допустимые переходы (`OrderService.AllowedTransitions`)

| Из | В |
|---|---|
| Created | Processing, Cancelled |
| Processing | Shipped, Cancelled |
| Shipped | Delivered |
| Delivered | — (финальный) |
| Cancelled | — (финальный) |

Из `Shipped` отменить нельзя. Повтор того же статуса — не ошибка, ничего не меняется. Любой другой переход — 400.

## Что происходит при переходах

| Событие | Остаток товара | Выручка / счётчики |
|---|---|---|
| Создание заказа (`Created`) | списывается условным `UPDATE ... WHERE Stock >= q`, в одной транзакции с заказом и промокодом | заказ попадает в «Заказов сегодня» и «Выручку сегодня» |
| Created→Processing→Shipped→Delivered | не меняется | не меняется (выручка не привязана к «доставлен»: оплата при получении) |
| Любой открытый → `Cancelled` | возвращается (`IncrementStockAsync`) в той же транзакции, ровно один раз | заказ выпадает из «сегодня» и «выручки» |

## Атомарность и гонки

- Списание остатка суммируется **по товару** (все размеры и повторные строки одного `ProductId` — общий остаток), идёт по возрастанию `ProductId` (нет дедлоков).
- Нехватка остатка: `Result.ErrorCode = out_of_stock` → **409** с названием товара; откатывается всё.
- Смена статуса — compare-and-set (`TryChangeStatusAsync`, `WHERE Status = ожидаемый`). Из двух гонящихся запросов выигрывает один; проигравший получает `conflict` → **409**.
- Отмена возвращает остаток только тем запросом, который реально перевёл заказ в `Cancelled`. Повторная отмена остаток второй раз не вернёт.
- Количество ≤ 0 отклоняется до списания (иначе условный UPDATE увеличил бы остаток).
- Размер: строка с недоступным размером — 409 `size_unavailable`, ничего не списывается.

## Idempotency-Key (`POST /api/v1/orders`)

- Заголовок необязателен; сайт и mobile шлют всегда. Формат `[A-Za-z0-9._:-]{8,100}`, иначе 400.
- Ключ захватывается **первым шагом транзакции заказа** (`INSERT ... ON CONFLICT DO NOTHING`), ответ сохраняется в той же транзакции. Таблица `IdempotencyKeys`, уникальный индекс (UserId, Key).
- Повтор с тем же телом: сохранённый ответ + заголовок `Idempotent-Replayed: true`, без второго заказа и списания. Параллельный запрос ждёт на индексе.
- Тот же ключ с другим телом (SHA-256 канонического JSON): **422** `idempotency_mismatch`.
- Отказ (нет на складе, размер и т.д.) откатывает транзакцию, ключ остаётся свободным.
- Срок 24 ч; `IdempotencyKeyCleanupService` чистит раз в час.
- Без заголовка повторное нажатие создаёт два заказа (клиенты ключ шлют всегда).

## Удаление аккаунта и заказы

Пока есть заказ в `Created/Processing/Shipped` — 409 `active_orders`. После «Доставлен» или «Отменён» аккаунт анонимизируется, заказы остаются без привязки к человеку.
