## 1.2 Общие принципы премиальности (обязательны везде)

- **Никаких мгновенных состояний** — любое изменение (hover, клик, появление элемента) анимируется через transition/transform, не через display:none/block скачком
- **Hover-состояния обязательны** на: кнопках, карточках товара, ссылках навигации, иконках (избранное/корзина)
  - Кнопки: небольшой подъём (`transform: translateY(-2px)`) + смена цвета фона + мягкая тень
  - Карточки товара: лёгкий zoom фото (`scale(1.03)`, overflow:hidden на контейнере), появление второй фотографии товара (если есть) или иконок действий
- **Фокус-состояния** для доступности (клавиатурная навигация) — видимый outline в акцентном цвете
- **Skeleton-загрузка** вместо спиннеров при загрузке товаров (серые прямоугольники-заглушки, пульсирующая анимация)
- **Плавный скролл**, элементы каталога появляются с fade+translateY при попадании во viewport (Intersection Observer, простая реализация без тяжёлых библиотек)
- Никакого системного `alert()`/`confirm()` — все уведомления через кастомные toast/модалки в стиле проекта

## 1.3 Хедер (Header) — sticky, обязательно проработать mobile и desktop раздельно

**Desktop (>1024px):**
- Логотип слева
- По центру: Женское / Мужское / Детское / Обувь и сумки (текстовые ссылки, hover — подчёркивание снизу анимированное слева направо, не мгновенное)
- Справа: иконка поиска (по клику разворачивается в строку поиска inline, не модалка), иконка аккаунта, иконка корзины со счётчиком (счётчик — маленький кружок с числом, анимация при добавлении товара — лёгкий bounce)
- При скролле вниз >100px — хедер уменьшается по высоте (компактный режим), но остаётся видимым (sticky, не исчезает)

**Mobile (<768px):**
- Логотип по центру, гамбургер-меню слева, корзина+поиск справа
- Гамбургер открывает fullscreen-меню (slide-in справа налево, с затемнением фона), не dropdown
- Внутри мобильного меню — категории крупным текстом, друг под другом

## 1.4 Главная страница

1. **Hero-секция**: 3 крупные плитки (Женское/Мужское/Детское) — на десктопе в ряд, на мобиле друг под другом. Фото + название категории (крупный текст, белый, поверх затемнённого фото) + подпись "Смотреть" с анимированной стрелкой при hover (сдвигается вправо)
2. **"Новинки недели"** — горизонтальный слайдер карточек (свайп на мобиле, стрелки на десктопе), не статичная сетка
3. **"Хиты продаж"** — по 2 блока (Женское/Мужское), аналогично слайдер
4. Footer: категории, контакты, соцсети, копирайт — тёмный фон (`--color-text` как фон, белый текст), обязательно на всю ширину, аккуратная сетка колонок

## 1.5 Карточка товара (ProductCard) — общий компонент, переиспользуется везде

**Состояния:**
- **Обычное**: фото (aspect-ratio 3:4), под фото — категория мелким серым, название, цена
- **Hover (desktop)**: фото плавно zoom (scale 1.03, transition-base), поверх фото появляются 2 круглые иконки (избранное — сердце, быстрый просмотр — глаз) с fade-in снизу вверх, если скидка — бейдж скидки остаётся поверх всегда
- **На мобиле**: hover-иконки не нужны — вместо них иконка избранного видна всегда в углу фото (полупрозрачный фон под иконкой)
- Цена: если есть скидка — старая цена зачёркнута серым, новая — акцентным/чёрным жирным

## 1.6 Каталог/страница категории

- Сетка: 1 колонка (мобиль) / 2 (планшет) / 4 (десктоп)
- Слева (desktop) или в выпадающей панели снизу (mobile) — фильтры: категория, размер, цена (слайдер диапазона), только со скидкой
- Сортировка: по цене, по новизне, по популярности — выпадающий список справа сверху
- Пагинация или infinite scroll (предпочтительно infinite scroll с skeleton-карточками при подгрузке)

## 1.7 Страница товара

- Слева/сверху (mobile) — галерея фото (свайп на мобиле, миниатюры сбоку на десктопе)
- Справа — название, цена, выбор размера (кнопки-квадраты, hover/selected состояния чётко различимы), выбор количества, кнопка "В корзину" (крупная, акцентная, с hover-подъёмом)
- Описание товара — раскрывающийся блок (аккордеон) если длинное
- Внизу — блок "Похожие товары" (та же карточка товара, слайдер)

## 1.8 Корзина

- Реализовать как **боковая выезжающая панель (drawer)**, не отдельная страница — открывается по клику на иконку корзины, slide-in справа с затемнением фона
- Список товаров с миниатюрой, названием, ценой, количеством (+/- кнопки), удаление (иконка корзины/крестик с hover-подсветкой)
- Итоговая сумма внизу, крупная кнопка "Оформить заказ"

## 1.9 Оформление заказа

- Отдельная страница, пошаговая (Step 1: доставка, Step 2: подтверждение) — визуальный индикатор прогресса шагов сверху
- Доставка: адрес (текстовые поля) + выбор способ (курьер/самовывоз — радио-кнопки в виде карточек, не стандартные radio input)
- Способ оплаты: пока единственный вариант "Оплата при получении" (заглушка, т.к. платёжный шлюз не подключён) — честно показываем как единственную опцию, не имитируем несуществующую оплату картой
- Подтверждение: сводка заказа + кнопка "Подтвердить заказ" → экран успеха с номером заказа

## 1.10 Личный кабинет

- Вход/регистрация — единая форма с переключателем (табы "Войти"/"Регистрация"), не отдельные страницы
- Валидация полей в реальном времени (не только по клику submit) — ошибки появляются плавно под полем, поле подсвечивается красным контуром
- История заказов — список карточек заказа (статус цветным бейджем, дата, сумма, состав)
- Избранное — та же сетка ProductCard, что и в каталоге

## 1.11 Кнопки — единая система вариантов

- **Primary**: заливка акцентным цветом, белый текст, hover — темнее + подъём
- **Secondary**: обводка акцентным цветом, прозрачный фон, hover — заливка акцентным
- **Ghost/text**: без фона и обводки, только текст с подчёркиванием на hover
- Все кнопки: `border-radius: var(--radius-md)`, паддинги минимум 12px/24px, курсор pointer, transition на все свойства

# ЧАСТЬ 2. BACKEND — Clean Architecture (уже начато, продолжить)

Структура уже создана (Domain / Application / Infrastructure / Api). Продолжить:

## 2.1 Domain
- Value Objects где уместно (напр. Money вместо decimal напрямую для цены, Email для валидации)
- Enum'ы: OrderStatus (Created, Processing, Shipped, Delivered, Cancelled), Gender (Male, Female, Kids)

## 2.2 Application
- FluentValidation для валидации входных DTO (не вручную if-ы)
- AutoMapper или ручной маппинг Entity↔DTO (на выбор, но единообразно)
- Паттерн Result<T> для возврата успех/ошибка из сервисов вместо исключений на бизнес-ошибки (исключения — только для непредвиденных сбоев)

## 2.3 Infrastructure
- Repository pattern + Unit of Work
- EF Core: индексы на часто фильтруемые поля (Product.CategoryId, Product.Gender, Order.UserId)
- Seed-данные для разработки (несколько тестовых товаров с плейсхолдер-фото, категории)

## 2.4 Api
- Global exception handling middleware (единый формат ошибок в ответах API)
- Стандартизированный формат ответа (ApiResponse<T> с success/data/errors)
- Версионирование API (`/api/v1/...`) на будущее
- Swagger с описаниями endpoints (XML-комментарии или атрибуты)

# ЧАСТЬ 3. БЕЗОПАСНОСТЬ (senior-уровень, обязательна проверка перед деплоем)

## 3.1 Аутентификация/авторизация
- Пароли: BCrypt/Argon2, минимум 10-12 раундов
- JWT: access-токен живёт 15 минут, refresh-токен 7-14 дней, хранится как httpOnly secure cookie (не localStorage!)
- Refresh-token rotation: при обновлении старый refresh-токен инвалидируется
- Роли (User/Admin) через claims в JWT, авторизация на уровне контроллеров (`[Authorize(Roles = "Admin")]`)

## 3.2 Валидация и защита от инъекций
- Все входные данные валидируются на backend (FluentValidation), фронтенд-валидация — только UX, не защита
- EF Core параметризованные запросы (by default) — не использовать raw SQL с конкатенацией строк
- Санитизация пользовательского ввода перед выводом (защита от XSS) — React экранирует по умолчанию, но проверить любые `dangerouslySetInnerHTML` (не использовать вообще)

## 3.3 Сетевой уровень
- CORS: строго указанный whitelist origin (домен фронтенда), не `AllowAnyOrigin`
- HTTPS enforced (redirect с HTTP), HSTS header
- Security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy` базовый

## 3.4 Rate limiting
- На `/api/auth/login` и `/api/auth/register` — строгий лимит (напр. 5 попыток/минуту с одного IP), защита от брутфорса
- Общий rate limit на API (напр. 100 запросов/минуту на IP)

## 3.5 Секреты и конфигурация
- JWT secret, строка подключения к БД — через переменные окружения / user-secrets в разработке, НЕ хардкод в appsettings.json перед деплоем
- `.gitignore` обязательно исключает файлы с реальными секретами

## 3.6 Логирование и аудит
- Логирование неудачных попыток входа, ошибок сервера (Serilog или встроенный ILogger)
- Не логировать пароли/токены в открытом виде

## 3.7 Прочее
- Проверка зависимостей на уязвимости (`dotnet list package --vulnerable`, `npm audit`) — исправить критичные перед деплоем
- Ограничение размера загружаемых файлов (если будет загрузка фото товаров через админку в будущем)

# ПОРЯДОК ВЫПОЛНЕНИЯ (для автономной работы)

1. Frontend: дизайн-система → хедер → главная → карточка товара → каталог → страница товара → корзина → оформление заказа → личный кабинет
